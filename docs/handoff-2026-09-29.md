## Gotchas learned the hard way

- **The auto-mode permission classifier blocks some root actions**: `certbot delete`, `apt purge` of a telemetry agent, journald size changes, and creating users / DB roles / ownership changes. When blocked: don't retry or work around it; write a reviewed script into `docs/runbooks/` and have the owner run it (`sudo bash … | tee /root/cleanup-2026-09/…log`), then verify from outside.
- `sudo -iu <user> bash -lc '…'` does **not** load nvm (Ubuntu `.bashrc` returns early when non-interactive). Use `sudo -iu <user> bash -c 'source ~/.nvm/nvm.sh; …'`.
- `$$` inside `ssh 'sudo bash -c "…"'` expands to a PID; use a quoted heredoc (`ssh IncServer 'sudo -n bash -s' <<'EOF'`).
- `sed` range deletes on nginx files: one ate the port map's closing `}`. Always `nginx -t` before reload and abort on failure.
- GNU `chmod u=rwx,go=rx` keeps setgid on directories; add `g-s`.
- `[ a ] && [ b ]` doesn't trip `set -e`.
- After a reboot, prod Next needs ~60 s of cold start before the first 200; GlitchTip likewise.
- `nc -z` reports both "refused" and "filtered" as closed: use `curl -v` / `nc -v` to tell a firewall drop from nothing listening (an earlier wrong claim about IPv6 came from this).
- From a non-TTY, run Ansible with `< /dev/null` and output redirected to a file (KuuakServer README).
- Never print secrets: inspect shapes (key names, lengths) only.
